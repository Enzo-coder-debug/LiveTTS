# LiveTTS 展示站

独立公开项目 `Enzo-coder-debug/LiveTTS` 的 GitHub Pages 网站。按用户要求直接采用 `LiveTTS对外页面.html` 的完整中文页面：原始 CSS、导航、首页、能力介绍、解耦说明、能力矩阵、六组评测、演示卡片、场景、接入步骤与相关文档均保留，不再使用此前重写的简化版。原文中的统计、竞品比较和结论为附件内容复现，不代表本次实施的独立核验。

仅作接入调整：样式提取为外部 CSS，原文增加控制台绑定；原演示卡片打开音频弹窗；团队内部文档 URL 不进入公开仓库，保留标题并弹出访问说明。Zero-shot 原始演示、SVC 和哼唱尚无可公开对应媒体，不拿当前预置音色样音冒充。后台和弹窗不改变原页面的默认布局。音频示例数量与附件中的模型能力统计不是同一口径。

## 本地预览与检查

```sh
python3 -m http.server 7862 --bind 127.0.0.1
node scripts/validate.mjs
```

访问 `http://127.0.0.1:7862/`。静态检查覆盖双语文案、HTML ID、分类、资源路径、输出元数据、评测数值与公开文件安全检查。8 个未提供参考录音的案例会产生预期 warning；本组没有空输出。

`node scripts/validate.mjs --release` 是更严格的参考对照完整性检查，要求每个案例参考录音、参考文本与所有输出齐备，当前有意不满足。普通预览部署不声称完成独立评测或媒体授权审核。

## 更新音频

### 使用可视化控制台（推荐）

在本机双击 `启动控制台.command`，或运行 `node scripts/console-server.mjs --open`。需要 Node.js 22+；公开发布还需要已经通过 `gh auth login` 登录的 GitHub CLI。控制台只监听 `127.0.0.1:7863`，不是公开网站上的无鉴权管理后台。重复启动会重新打开现有控制台。

1. **音频与文案**：按分组浏览、搜索和试听；编辑中英文名称、真实合成文本、模型与参数；替换或新增 WAV；上下调整条目/分组顺序，勾选是否展示。
2. **网站设置**：修改首页和各区块中文文案、公开资源链接。空白文案使用附件原文；附件布局为中文，旧英文配置保留但不显示为混合翻译页面。
3. **保存修改**：先校验，再写入本地文件，自动保存上一版备份。上传音频先暂存，以内容 SHA-256 命名，保存时才进入公开资源目录。
4. **预览网站**：先保存，再打开本地预览；不会直接改变官网。
5. **发布到官网**：确认音频、文案与授权后，提交到固定项目 `Enzo-coder-debug/LiveTTS`，并显示 Pages 部署状态。检测到远端新提交时停止，不强行覆盖。

编辑文本**不会重新合成音频**。替换文件限 16-bit PCM WAV、单/双声道、8–192 kHz、0.1 秒至 10 分钟、45 MB 以内；拒绝空白或近静音文件。其他现有音频格式可以保留，但控制台当前仅接受 WAV 上传。

“发布与备份”可恢复上次保存前的内容，仅影响本地；如需官网回退，恢复后再次发布。旧音频仍保留，隐藏条目只取消展示，**不等于撤回已公开文件**。需彻底下架的文件应从仓库资源中移除后重新发布。

控制台源代码进入 GitHub 仓库，但 Pages 工作流**不发布 `console/` 或 `scripts/`**。会话凭证、GitHub 发布基线、上传暂存及备份位于 `.generation/`，均不得上传。访问受本机 Host、同源写入和 HttpOnly 会话校验保护；GitHub 令牌只由本机 `gh` 使用。

控制台保存时更新 `assets/audio/CATALOGUE.json` 的当前文件校验记录；`GENERATION.md` 及本 README 的 36 条音频统计描述 2026-11-10 的这次发布，不会冒充后续手动上传文件的生成记录。

### 手动更新

将获准公开的文件放入 `assets/audio/`，在 `data.js` 填写对应输出的 `src`、实际输入 `text`、请求版本 `model` 与参数 `settings`，设置 `illustrative: false`。只有非空且非示意的输出进入试听区，数量自动更新。

本轮使用 `scripts/synthesize_timbre_samples.py` 调用团队指定的 HTTP 脚本，通过 `--jobs` 指定审核后的输入与标签、`--timbre-id` 指定音色、`--destination` 指定私有生成目录。凭证仅通过环境变量 `LIVETTS_API_KEY` 或显式 `--credential-script` 读取。脚本在内存中移除旧 fid、覆盖 tim 与 model_version，不改动原始脚本；支持 `--only case-id/index`、`--dry-run`，已有结果按请求签名与 SHA-256 校验复用。

生成结果与请求日志只存入忽略的 `.generation/`；**不得上传此目录**。公开前核对文本、文件、版权与发布范围，只复制审核后的音频和去敏元数据。

## 部署

仓库的 `.github/workflows/livetts-pages.yml` 使用 `SITE_DIR: livetts-github`。主分支网站文件更新后自动发布，也可手动触发。仅允许的网页文件和 `assets/` 进入 Pages，不发布本地脚本日志、凭证或体验页后端。

公共链接在 `site.config.js` 配置。仓库部署说明副本位于 `deployment/REPOSITORY_README.md`，工作流副本位于 `deployment/pages-monorepo.yml`。不修改其他项目仓库。

模型权重、音色、API、音频素材和代码的许可需分别确认，公开展示不等于授予使用许可。
